# ヘルプ執筆ルール（ビルド対象外）

このディレクトリの `NN_slug.md` が StirHex 同梱ヘルプの原稿。
`python porting/tools/build_help.py` で `porting/StirHex/help/*.html` を生成する。
アンダースコアで始まるファイルはビルド対象外（このファイル自身）。

## 絶対に守る制約

1. **原版ヘルプ（`analysis_target/Stirling.hlp.md`）を読まない・引用しない・言い換えない。**
   原作者ＤＤＳ２氏の著作物であり、同梱・再配布できない。文章はすべて自前で書き起こす。
2. **実装を読んで書く。** 根拠は `porting/StirHex/src/` 配下のソース、`porting/StirHex/res/StirHex.rc`
   のメニュー・ダイアログ定義、`analysis_artifacts/docs/*.md`（移植側の解析メモ）。
   推測で機能を書かない。ソースで確認できなかったことは書かずに申し送りする。
3. **未実装・原版と挙動が異なる箇所は明記する。** 「未実装」「移植版では〜」とはっきり書く。曖昧にしない。
4. UI 上の文言（メニュー項目名、ダイアログのラベル、ボタン名）はリソース定義の表記と一字一句合わせる。

## 文体

- 常体ではなく「です・ます」。二人称は「操作する人」を主語にせず、動作を主語にする書き方を優先する。
- 1 文を短く。手順は番号付きリスト、対応表は Markdown テーブル。
- キー表記は `Ctrl+A` のように半角プラス区切り。メニューは `[ファイル]→[開く]` 形式。
- メニュー項目・ダイアログ項目の名前からアクセラレータ記号は落とす。
  リソースが `ファイル(&F)` でも本文では `[ファイル]`、`開く(&O)...` でも `[開く]` と書く。
  一字一句合わせるのは表記そのもの（送り仮名・中黒・カタカナ）であって、`(&X)` と末尾の `...` は含めない。
- 内部の変数名・関数名・クラス名を本文に出さない。読者が画面から確認できる言葉で書く。

## 使える Markdown（ビルダの対応範囲）

見出し `#`〜`######` / 段落 / `-` `*` 箇条書き（ネストは半角 2 スペース）/ `1.` 番号付き /
GFM テーブル / `>` 引用 / フェンスコードブロック / `---` 水平線 /
`**強調**` / `*斜体*` / `` `コード` `` / `[表示文字](リンク先)`

これ以外の記法（HTML 直書き、脚注、定義リスト、画像）は使わない。

## ファイル構成

- 各ファイルの先頭に `# ` 見出しを 1 つだけ置く。これが章タイトル兼ページタイトルになる。
- `##` 見出しが目次に載る。章内の節は `##`、その下は `###` を使う。
- 他の章へのリンクは `[2. 基本操作](02_basics.html)` のように **生成後の .html** を指す。
