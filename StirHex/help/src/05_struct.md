# 5. 構造体編集

## 構造体編集バーの使い方

### 表示と各部の役割

[編集]→[構造体編集]または[設定]→[構造体編集]で、構造体編集バーの表示と非表示を切り替えます。起動直後は非表示です。

バーを表示すると、設定に従って、アクティブな文書のキャレット位置または保存済みの先頭アドレスを基準に構造体を表示します。バーを非表示にすると、データ表示領域に付いていた構造体範囲の青い強調表示も解除されます。

構造体編集バーには、次の部品があります。

| 部品 | 役割 |
| ---- | ---- |
| [再読込] | StirHex.exe と同じフォルダーにある Struct.def を読み直します。 |
| 構造体名の選択欄 | 読み込んだ構造体の一覧から、表示する構造体を選びます。 |
| 先頭アドレス | 現在の構造体を解釈するデータ位置を、8桁の16進数で表示します。 |
| [<<] / [<] / [移動] / [>] / [>>] | 構造体の先頭アドレスを移動します。 |
| メンバー一覧 | [型]、[シンボル名]、[値]の3列で、構造体の内容を表示します。 |
| [閉じる] | バーを非表示にします。 |

構造体を選ぶと、先頭アドレスから構造体のサイズ分を読み込み、メンバー一覧を作成します。構造体の範囲は、データ表示の16進領域でも青く強調されます。

構造体を選んでいない場合や、アクティブな文書がない場合は、メンバー一覧は空になります。

### メンバー一覧の見方

[型]には型名、[シンボル名]にはメンバー名、[値]には現在のデータから解釈した値が表示されます。配列や構造体型のメンバーには階層があり、[+]と[-]で展開・折りたたみができます。

配列は、メンバー名の後ろに要素数が表示され、展開すると各要素が表示されます。2次元配列は、行と要素の2段階で展開されます。

ネストした構造体も展開できます。構造体型や配列の親行は容器であり、値を直接編集する行ではありません。編集できるのは、実データが存在するスカラー型の葉です。

`char` または `byte` の配列は、親行の[値]に文字列として表示されます。親行を編集するのではなく、展開した各要素を編集します。文字列化には現在のキャラクターセットが使われます。

構造体全体またはメンバーの一部が文書の範囲外になる場合、値は `----` と表示され、その行は編集できません。移植版では、不足しているデータを保存時に自動追加する処理はありません。

スカラー行を右クリックすると、[編集]と基数の指定項目が表示されます。配列やネストした構造体の行では、先頭項目が[開く]または[閉じる]に変わります。

[一括基数指定]では、すべてのスカラー値を[符号付き10進表示]、[符号なし10進表示]、[16進表示]のいずれかで表示できます。[デフォルトに戻す]で型ごとの既定値に戻ります。

[個別基数指定]では、選択したスカラー行だけの表示基数を変更できます。基数指定は表示だけを変え、文書のバイト列は変更しません。`float` と `double` は常に浮動小数表示です。

### 値を編集して書き戻す

編集可能なスカラー行をダブルクリックするか、行を選んで `F2` または `Enter` を押すと、[値]の位置に入力欄が表示されます。

入力欄で `Enter` を押すと確定し、`Esc` を押すと取り消します。入力欄からフォーカスを外した場合も、入力内容を確定します。

確定した値は、選択中の型、バイトサイズ、バイトオーダーに従ってバイト列へ変換されます。変換に成功し、値が現在の値と異なる場合だけ、同じサイズのデータとして文書へ書き戻します。

構造体バーからの書き戻しは、1回の元に戻す操作の対象です。書き戻し後はデータ表示と構造体バーが更新されます。

編集禁止中の文書では、値を編集できません。入力が空、不正な数値、範囲外の数値、または構造体の範囲外の場合は、書き戻さずにビープ音を鳴らします。

整数値は通常10進数で入力します。先頭に `0x` または `0X` を付けると16進数になり、10進数の負数には先頭の `-` を使います。整数入力に前後の空白や、16進数の負号は使えません。

`float` と `double` は小数点と符号を使えます。指数表記の `e`、`E`、`d`、`D` の直後には、`+` または `-` が必要です。入力全体が値として解釈できない場合は書き戻されません。

### 先頭アドレスを移動する

[<<]と[>>]は、現在選んでいる構造体のサイズ単位で先頭アドレスを前後へ移動します。[<]と[>]は1バイト単位で移動します。

文書の先頭より前、または構造体全体が文書に収まらない位置へは移動できません。境界で移動できない場合はビープ音が鳴ります。

[移動]を押すと、[先頭アドレスの指定]ダイアログが表示されます。

| 項目 | 内容 |
| ---- | ---- |
| [アドレス指定] | 数値を入力して先頭アドレスを指定します。 |
| [マーク登録位置] | 登録済みマークの一覧から先頭アドレスを選びます。 |
| [アドレス] | 絶対アドレスまたはキャレット位置からの相対値を入力します。 |
| [アドレスベース] | [10進]または[16進]を選びます。 |
| [OK] | 指定を確定します。 |
| [キャンセル] | 移動を取り消します。 |

[アドレス指定]では、符号なしの入力は絶対アドレスです。`+N` は現在のキャレット位置から `N` バイト後ろ、`-N` は現在のキャレット位置から `N` バイト前を指定します。

アドレス欄は空欄、前後の空白、基数にない文字を受け付けません。16進数では `0`～`9` と `A`～`F`（大文字・小文字）を使えます。`0x` の接頭辞は使いません。

[マーク登録位置]を選ぶと、アドレス入力欄と[アドレスベース]が無効になり、一覧からマークを選べます。マーク行をダブルクリックして確定することもできます。

アドレスの指定結果が文書の範囲内でも、選択中の構造体全体が収まらない場合は、構造体バー側で移動を拒否します。

環境設定の[現在位置を構造体編集アドレスに自動設定]を有効にすると、バーを表示したときやアクティブな文書を切り替えたときに、先頭アドレスがその文書のキャレット位置へ同期します。バーを表示している間、キャレット移動へ常時追従する設定ではありません。

この設定を無効にすると、ドキュメントウィンドウごとに最後に操作した構造体の先頭アドレスを保持します。別のドキュメントウィンドウを初めて表示した場合の基準アドレスは0です。

「キャレット位置を構造体編集」に割り当てられた操作を実行すると、選択中の構造体の先頭アドレスを現在のキャレット位置へ設定できます。構造体全体が収まらない場合は設定されません。

## Struct.def の書式

### ファイルの場所と文字コード

Struct.def は StirHex.exe と同じフォルダーに置きます。構造体編集バーの生成時と[再読込]の実行時に、その場所から読み込まれます。

定義ファイルはCP932（Shift-JIS）のバイト列として扱われます。構造体名とメンバー名に使える文字はASCII範囲に限られるため、構文部分はASCII文字で記述してください。

### 最小の定義例

次の例は、この章のために作成した定義です。

```c
/* Header is defined before Record. */
struct Header {
    BYTE magic;       // one byte
    WORD version;
    char name[8];
};

struct Record {
    Header header;
    dword length;
};
```

構造体は `struct`、名前、`{`、メンバー列、`}` の順に書きます。各メンバーは、型名、メンバー名、必要なら配列指定、`;` の順に書きます。

組み込み型では、型名の大文字・小文字が既定の表示基数を決めます。`BYTE` と `WORD` のように大文字で書く型は、既定で16進表示になります。

最後の `;` まで含めて、C形式の構造体定義として記述してください。1つのメンバー宣言に複数の名前をカンマで並べる書式は使わず、1メンバーずつ宣言します。

### 複数の構造体とコメント

1つのStruct.defに、構造体定義を複数続けて書けます。後で定義した構造体のメンバー型として、先に定義した構造体名を使えます。

例の `Record` では、先に定義した `Header` をメンバー型にしています。`struct Header header;` のように `struct` を付けた書き方も受け付けます。

前方参照は使えません。`Record` の後に `Header` を定義する順序では、`Header` を型として解決できません。

コメントは、行末までの `//` コメントと、`/*` から `*/` までのブロックコメントに対応しています。`#include`、`typedef`、マクロ、文字列リテラルは定義ファイルの書式として扱われません。

## 使用できるデータ型と既定の基数

### 組み込み型

| 型名 | サイズ | 既定の表示 | 符号・値の解釈 |
| ---- | ----: | ---- | ---- |
| `char` / `CHAR` | 1バイト | 符号付き10進 | 符号付き8ビット |
| `byte` | 1バイト | 符号なし10進 | 符号なし8ビット |
| `BYTE` | 1バイト | 16進 | 符号なし8ビット |
| `short` / `SHORT` | 2バイト | 10進 | 現在の実装では符号なし16ビットとして読み取ります |
| `word` | 2バイト | 符号なし10進 | 符号なし16ビット |
| `WORD` | 2バイト | 16進 | 符号なし16ビット |
| `long` / `LONG` | 4バイト | 符号付き10進 | 符号付き32ビット |
| `dword` | 4バイト | 符号なし10進 | 符号なし32ビット |
| `DWORD` | 4バイト | 16進 | 符号なし32ビット |
| `float` / `FLOAT` | 4バイト | 浮動小数 | 単精度浮動小数点 |
| `double` / `DOUBLE` | 8バイト | 浮動小数 | 倍精度浮動小数点 |

16進表示は `0x` を付け、型のサイズに合わせて桁をそろえます。`float` と `double` は、基数指定を変更しても浮動小数表示のままです。

`short` と `word` はどちらも2バイトの値を符号拡張せずに読み取ります。型名と既定の表示基数は別に扱われるため、`short` という名前でも負の値として表示されるとは限りません。

### 配列と構造体型

配列は1次元または2次元に対応しています。要素数は正の10進整数で指定し、`[N]` または `[N][M]` の形式を使います。要素数0、16進表記、符号付き指定は使えません。

1つの次元の要素数と、2次元配列の要素数の積には、実装上65536という上限があります。配列の各要素はメンバー一覧で展開できます。

組み込み型ではない型名は、先に定義された構造体名として解決されます。構造体型のサイズは、メンバーのサイズを順に合計して決まります。C言語のアラインメントによる自動パディングは入りません。

ポインタ、ビットフィールド、`unsigned` 前置、`typedef`、組み込み型以外の別名には対応していません。インラインで本体を書くネスト構造体も対応していないため、名前を付けて先に定義してください。

`char` または `byte` の1次元配列は、配列要素の展開に加えて、親行の値へ文字列を表示します。文字列表示に使うデータは先頭256バイトまでです。

### バイトオーダー

構造体バーは、現在の文書で選ばれているバイトオーダーを値の読み取りに使います。2バイト、4バイト、8バイトの整数・浮動小数点値では、[設定]→[バイトオーダー]の選択によって値が変わります。

値を編集して確定するときも、同じバイトオーダーで文書へ書き戻します。`char`、`byte`、文字列として表示する配列の1バイト要素には、バイトオーダーは影響しません。

## 制限事項

### 識別子に使える文字

構造体名とメンバー名は、`A`～`Z`、`a`～`z`、`0`～`9`、`_` の文字だけで構成できます。字句解析では先頭文字だけを特別扱いしないため、数字や `_` から始まる名前もトークンとして受け付けます。

日本語などの非ASCII文字は識別子として認識されません。非ASCIIの構造体名やメンバー名を使うと、定義名の読み込みに失敗するか、メンバー宣言として解釈されません。

定義名とメンバー名は大文字・小文字を区別します。組み込み型も大文字・小文字を区別し、同じ語でも既定の表示基数が変わる型があります。

### ネストと非対応の宣言

名前を付けたネスト構造体と、1次元・2次元配列は対応しています。ネスト構造体は、使用する前に定義を置く必要があります。

ポインタ、ビットフィールド、`typedef`、`unsigned`、関数宣言、複数メンバーを1文にまとめるC形式は対応していません。これらを含む定義をそのまま読み込ませないでください。

### 定義ファイルの読み込みエラー

構造体編集バーの初回生成時と[再読込]の実行時に、Struct.def は読み直されます。読み込み開始時に、以前の定義は一度クリアされます。

Struct.def が存在しない場合は、エラーメッセージを表示しません。構造体名の一覧は空になり、構造体編集バーは使用できません。

Struct.def が存在し、ファイルを開けない場合や、パーサが配列要素数の不正、未定義の型、構造体宣言の不正などをエラーとして返した場合は、エラーメッセージが表示されます。メッセージには読み込み理由が含まれます。

エラーになる前に読み込まれた定義が保持されている場合は、エラーメッセージの後も、その定義が構造体名の一覧に表示されることがあります。

空のファイルや、パーサが記号を読み飛ばしてエラーとして返さない書式では、エラーメッセージが表示されない場合があります。未対応の書式を使わず、ここで説明した文法で記述してください。
