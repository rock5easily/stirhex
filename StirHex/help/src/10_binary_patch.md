# 10. バイナリパッチ
バイナリパッチは、ディスク上のファイル全体を比較して差分ファイルを作成し、元ファイルへ差分を適用する機能です。開いている文書の未保存内容は対象になりません。

## パッチを作成する

1. [ツール]→[パッチを作成]を選びます。文書を開いていなくても実行できます。
2. [元ファイル]へ変更前のディスク上のファイルを指定します。
3. [変更後ファイル]へ変更後のディスク上のファイルを指定します。
4. [形式]で BPS または IPS を選びます。
5. [パッチファイル]へ保存先を指定します。形式に応じて保存ダイアログの既定の拡張子が変わります。
6. [作成]を押します。

BPS は既定の形式で、ファイルサイズが変わる差分にも対応します。元ファイルの内容とサイズを検証できる情報をパッチへ含めます。

互換性を重視し、IPS の生成は元ファイルと変更後ファイルが同じサイズで、双方が16MiB以下の場合に制限しています。条件を満たさない場合は BPS を使用してください。IPS は通常レコードと RLE（同じ値の繰り返し）を使って作成し、EOF の後ろに結果長を指定する拡張は生成しません。

## パッチを適用する

1. [ツール]→[パッチを適用]を選びます。文書を開いていなくても実行できます。
2. [元ファイル]へパッチ適用前のディスク上のファイルを指定します。
3. [パッチファイル]へ IPS または BPS のパッチを指定します。
4. [結果ファイル]へ出力先を指定します。
5. 適用後に結果を開く場合は、[成功時に結果ファイルを開く]を有効にします。
6. [適用]を押します。

パッチ形式はファイルのマジックから自動判別します。[形式]の表示は選択できません。IPS は元ファイルの内容を検証しないため、ダイアログに注意が表示されます。元ファイルを確認してから[適用]を実行してください。IPS は16MiBを超える元ファイルにも適用できます。異なるサイズの出力や、EOFの後ろに拡張長を指定したパッチにも対応します。

BPS は4種類の命令を処理し、元ファイル・パッチ・作成結果のCRCを検証します。検証に失敗した場合、結果ファイルは公開されません。

## 共通の制限

- 入力はディスク上のファイル全体です。編集中で未保存の内容、選択範囲、マーク、アンドゥ履歴は使いません。
- パッチ作成では[パッチファイル]の保存先を元ファイル、変更後ファイル、または開いている文書と同じファイルへ指定できません。パッチ適用では[結果ファイル]の保存先を元ファイル、パッチファイル、または開いている文書と同じファイルへ指定できません。ハードリンクも同じファイルとして扱います。
- 結果は一時ファイルへ作成してから保存先へ転送します。転送中は[中止]でキャンセルできます。保存先への最終確定中は中止できません。
- 保存先のファイルが既に存在する場合は、[適用]または[作成]の開始時に上書き確認が表示されます。
- 適用後に結果を開く操作は通常のファイルオープンです。元ファイルや開いている文書の内容、マーク、アンドゥ履歴は変更しません。
- 保存先への置換に特定の障害が起きて回復用ファイルのパスが表示された場合は、そのファイルを自動削除しません。メッセージに表示された場所から手動で回復してください。

ファイルサイズが大きい場合は処理に時間がかかります。現在の制限は次のとおりです。

- IPS の生成は、元ファイルと変更後ファイルが同じサイズで、双方16MiB以下です。
- BPS の生成は、元ファイルと変更後ファイルがそれぞれ256MiB以下です。
- IPS または BPS の適用は、元ファイルと結果ファイルがそれぞれ512MiB以下、パッチファイルが512MiB以下です。IPS は16MiBを超える元ファイルにも適用できます。
- BPS の命令数は約1600万、IPS のレコード数は約400万です。IPS の展開データ、BPSの探索メモリ、処理用一時ファイル（1GiB）にも上限があります。

これらの制限を超える場合や、必要なメモリ・ディスク領域を確保できない場合は処理を実行できません。進捗表示が更新されている間は、ダイアログを閉じずに完了または[中止]を待ちます。
